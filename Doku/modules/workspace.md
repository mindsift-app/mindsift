# Module: Workspace (Outliner Notes)

Code: [WorkspaceView.tsx](../../frontend/src/features/workspace/WorkspaceView.tsx) (explorer, tags, to-do rollup), [DocumentEditor.tsx](../../frontend/src/features/workspace/DocumentEditor.tsx) with its hooks (`useDocumentSync`: loading, sync engine, save status; `useNotePlace`: zoom, remembered place, browser history; `useEditorLayout`: title field, focus mode position, keyboard, cursor kept in place; `useDocPresence`: presence and locks; `useBranchActions`: undo/redo, extract, move, pull back; `useBlockEditing`: edits of the outline; `useTagPage`: hashtag page), [OutlinerTree.tsx](../../frontend/src/features/workspace/OutlinerTree.tsx), [OutlinerBlock.tsx](../../frontend/src/features/workspace/OutlinerBlock.tsx), [CodeBlockEditor.tsx](../../frontend/src/features/workspace/CodeBlockEditor.tsx), [LinkModal.tsx](../../frontend/src/features/workspace/LinkModal.tsx); Backend: document, folder, and tag handlers, sync handler in `internal/api/docsync.go`, `internal/collab`, `internal/storage/docsync.go`.

## Data Storage

- A note is a record in `documents` plus a tree of blocks in `blocks` (`parent_id`, sort key `order_key`). Every change goes through `internal/collab` and is recorded in the `doc_ops` log. Depth level and position for the UI are calculated by the server on read. The log and deleted blocks are compacted regularly ([database.md](../database.md#verdichtung-des-notiz-logs)). Everything resides in SQLite; there are no files on disk.
- On every change, `block_tags` is rebuilt from `#hashtags` in the blocks. Markdown and plain text are built from the blocks when a note is read (`documents.content` stays empty since Migration 44, `documents.markdown_cache` was dropped by Migration 48); the journal, too, takes whether a day has text from the blocks.
- **Hashtag rule:** `#word` only counts at the start of text or after whitespace or `(`. Anchors in links (`example.com/blog#heading`) and words like `C#` are not tags. The same rule applies on the server (`domain.ExtractTags`) and in the browser (`lib/hashtags.ts`). On first start after migration, `migrateAnchorTags` runs a one-time cleanup of stored tags that originated solely from anchors.
- Export as `.md` is handled in the browser (button in editor, blob download).
- Block types: Headings `h1`–`h3`, `paragraph`/`text`, `bullet`, `todo`, `code`, `callout`, `divider`, `table`, `progress`, `drawing`.
- **Drawings** (`drawing`, prototype): the block content is a small JSON model (`lib/drawing/model.ts`: shapes, text, arrows docked by element id, freehand points, optional `frame` and `grid`), never SVG markup; React renders it as SVG with theme colour roles. The preview (`drawing/DrawingBlock.tsx`) fills the note's width and fits everything up to 420 px high, or shows the saved `frame` scaled to the width; its height follows the width. A size toggle (`nextSize`, stored as `fit`) switches between this automatic size and the other one: `all` (the whole drawing as large as the width allows, for tall drawings) or `readable` (the recommended height at a readable size, for wide drawings, starting at their left); from a saved `frame` it goes back to automatic. A click focuses the preview: dragging moves the section, Ctrl/Cmd + wheel or pinching zooms, the wheel alone keeps scrolling the page; a click without dragging (or one outside, Escape) leaves it and an unsaved section glides back. The full-screen editor (`drawing/DrawingEditor.tsx`) keeps changes local, stores a draft in `localStorage` and writes the block once on closing (`set_content`, at most 100 KB like any block; offline it waits in the sync queue like typed text). The drawing's buttons (edit, save view, automatic) go into the bullet's action bubble through a portal. A click into the drawing or the open editor counts as the cursor in that bullet, so the editor holds the block's lease (others see the lock and only look); while drawing it calls `touchBlock` on the sync engine every few seconds, so the lease does not run idle after 60 s. The server (`internal/drawing`) rejects non-empty content that is not a drawing model for `drawing` blocks, indexes only the words written in a drawing for search, describes drawings in words for MCP (`[Zeichnung: „Start“ → „Ziel“; …]`, free arrows with a label as `Pfeil „…“`) and renders them as SVG for the Markdown archive (`attachments/<blockId>.svg`, the model embedded as `<metadata id="mindsift-drawing">`, so importing the archive brings back editable drawings). Copied as Markdown, and in Markdown without files, a drawing is a fenced block ```` ```mindsift-canvas ```` holding its model; pasting or importing it gives a drawing again.
- **Arrows** dock to shapes by id (`from`/`to`); `a`/`b` keep the last computed ends for the server. Optional `via` corner points (laid out diagrams) are dropped as soon as a docked shape is moved or resized, an end is dragged or the route changes. `txt` is a label in the middle of the line (double-click the arrow).
- **Mermaid** (`internal/drawing/mermaid.go`, `layout.go`): agents send a flowchart/graph (`TD`/`LR`/`BT`/`RL`, shapes, `-->`/`---`/`-.->`/`==>`/`<-->`, labels, `style`/`classDef`/`class`/`:::`/`linkStyle` colours mapped to theme roles) a mindmap, a sequence diagram, a state diagram or a Git graph (details below). Flowcharts are laid out in layers (cycles reversed, longest-path layers, helper points for long edges, barycentre ordering against crossings, positions pulled to neighbours, right-angled lines with `via` through the gaps, each source on a track of its own per gap (its own lines share it as a fork; constrained left-edge with the vertical constraints of the gap, the gap grows with the tracks), so lines of different sources never lie on top of each other; lines entering the same side of a shape end side by side along its edge, ordered by where they come from, a line back against the arrows (a broken cycle) gets a track of its own, and lines between the same two shapes (A → B and B → A) run side by side, both ends moved apart; arrows are `elbow` with `fromPort`/`toPort`, like lines docked by hand); mindmaps put the branches on both sides of the root, a colour per branch, curved lines. The result is an ordinary drawing; layout is done once on the server, the editor never searches for ways. Lines the reader does not understand are skipped; a diagram without anything readable is an error (`ErrMermaidEmpty`), an unknown kind another one (`ErrMermaidKind`).
- **Sequence diagrams** (`mermaid_sequence.go`): participants (`participant A as …`, `actor` as an ellipse) in a row at the top and again at the bottom, joined by dashed lifelines (arrows docked to both boxes); messages are free level arrows from top to bottom (`->>`, `-->>` dashed, `->`/`-->` without head, `-x`/`--x` red, `-)` async, `<<->>` both ways), the text above the line; a message to oneself is an elbow loop with its text as a free text beside it. Column gaps grow until every message text and note fits between its lifelines. `Note left of/right of/over` are orange boxes; `loop`/`alt`/`else`/`opt`/`par`/`and`/`critical`/`break` … `end` frames (muted outline, condition as text, `else`/`and` as a dashed line), `rect <colour>` a coloured band, `box <colour> <label>` a group behind its participants; `autonumber` puts numbers in front of the texts; `activate`/`deactivate` and `+`/`-` are ignored. At most 40 participants and 300 items.
- **State diagrams** (`mermaid_state.go`): parsed into the flowchart graph and laid out by `layoutFlowchart`: `[*]` is a start dot (a small ellipse drawn filled by its thick line) or an end ring with a dot inside (one per scope), states are rounded boxes (`state "…" as X`, `X : description` lines add up), `<<choice>>` a small diamond, `<<fork>>`/`<<join>>` a bar (upright in LR), transitions keep their label. A composite state (`state X { … }`) is a box of its own; its inner start becomes a dashed arrow from it, its inner end a ring of its own. Notes (`note left of/right of X : …` or over several lines up to `end note`) are orange boxes joined by a dashed line without head. `direction`, `classDef`/`class`/`:::`/`style` as in flowcharts.
- **Git graphs** (`mermaid_git.go`): `commit` (`id`, `tag`, `type` NORMAL/HIGHLIGHT/REVERSE), `branch` (`order`), `checkout`/`switch`, `merge`, `cherry-pick`; `gitGraph LR:` (default), `TB:` or `BT:`. Each commit has a column of its own in the order written, each branch a lane in its own colour (`branchColors`, main first) with its name in a box at the start and a dashed lane line before its first and after its last commit. Commits are dots (a small shape drawn filled by its line), merges rings, HIGHLIGHT a square, REVERSE red; ids and tags stand on the side away from the lines (above in LR, left in TB). Lines to the parent: straight along a lane, an elbow across lanes (a new branch leaves its parent across first, a merge runs along the merged branch first), a cherry-pick dashed. At most 150 commits.
- **Elbow arrows in the editor** (`lib/drawing/model.ts`): `via` holds the corners of their own (laid out or moved by hand) and stays when a docked shape moves; the ends meet the shapes at right angles (`orthoDock`, or straight out of a port after a short stub). `fromPort`/`toPort` (`{side: t|r|b|l, at: 0…1}`) store where a line leaves and enters, set by dragging its end onto a side (`portNear`, snapping to the middle of the side; near the centre: none); the corners of its own stay, the new end reaches them over a short stub. Without corners an elbow runs halfway between its ends, up and down when there is more free space between its shapes above than beside them (`elbowHorizontal`), with ports along the shortest plain way between them (`connectPorts`). Every stretch has a handle (`fixedStretches`): full on stretches between two corners of its own, grey on made-up ones; dragging moves a stretch across and fixes it, at an end with a short stub so the end stays (`dragSegment`); a double click on a full one removes it and joins the corners around it (`releaseSegment`); stretches without length go when letting go (`settleCorners`). A line docked to a shape that stays behind does not move with a selection; it comes loose only by dragging its end. Labels that would cover each other move aside (`spreadLabels`: below a level line instead of above, up or down an upright one), worked out when a change is done and once per drawing in the note, not while dragging; nothing of it is stored.

## Editor

- **Outliner:** `Enter` new block, `Tab`/`Shift+Tab` indent/outdent, `Shift+Enter` soft line break, collapse/expand blocks.
- **Zoom (Hoisting):** Clicking a bullet focuses the branch; the breadcrumb bar navigates back. On phones (below `sm`) the header shows a home button instead of the path (with the zoomed bullet's name beside it only where it fits), which leaves the zoom and returns to the start of the note. Every zoom step is a step of the browser history, so back zooms out one level.
- **Drag & Drop** moves blocks including sub-branches; dragging onto another block turns it into a child item.
- **Slash commands:** `/todo`, `/link`, `/h1`, `/h2`, `/h3`, `/code` (with VS Code style syntax highlighting), `/callout`, `/divider`, `/extract` (extract branch into a separate note), `/image` (insert/upload images, aliases `/bild`, `/foto`), `/audio` (voice note/audio file, alias `/sprachnotiz`), `/diktat` (voice input with live transcription, alias `/dictate`), `/hidden` (hidden value, alias `/secret`, see below), `/canvas` (drawing, aliases `/draw`, `/sketch`, `/diagram`, `/zeichnung`), `/template` (insert a template, shown in the app's language as `/vorlage`, `/plantilla`, `/modèle`, `/modello`; every one of these names finds it in every language, see Templates below) (list in `OutlinerBlock.tsx`). The menu opens only at the start of text or after a space and closes with `Esc` or `Backspace`.
- **Templates** ([lib/noteTemplate.ts](../../frontend/src/lib/noteTemplate.ts), [NoteTemplates.tsx](../../frontend/src/features/workspace/NoteTemplates.tsx), [internal/storage/templates.go](../../internal/storage/templates.go)): a template is an ordinary note the person marks in its ⋯ menu ("Als Vorlage verwenden" / "Keine Vorlage mehr", `PUT /documents/{id}` with `isTemplate`). The mark is personal like the pin: one row per person and note in `doc_templates` (migration 61), so anyone may use any note they can read as their template (a read right is enough, also for a note shared with them), and nobody else sees that choice; a note shared with others is no template for them because its owner uses it as one. `isTemplate` comes with the note and the note list for the caller only. Templates stay wherever the person keeps them (the help suggests a folder "Vorlagen"; none is created); the folder tree shows a small mark behind their title and the note header a "Vorlage" pill. A note in the trash cannot be marked; deleting it for good removes the marks.
  - **`/template` (`/vorlage`)** opens a searchable picker (`PickerPopover`) of the person's templates at the bullet. The chosen template is loaded (`GET /documents/{id}`) and copied in like pasted bullets, through the same `onInsertBlocks` path as a paste: an empty text-like bullet becomes the template's first bullet, otherwise the copy follows the bullet's branch on its level; levels count from the template's shallowest bullet. Types, code languages, tables, drawings, pictures and hidden values come along (the server checks pictures with mediaGate and copies hidden values with secretGate, as for any paste: allowed because the person may read the template); to-dos start open and are linked to no task, nothing is collapsed, conflict copies are left out.
  - **"Neue Notiz":** with templates, the new-note sheet (phones always, the desktop only when the person has templates; without, it still creates at once) has a template field (`SelectMenu`, "Leere Notiz" first). The new note gets the title from the sheet and a copy of the template's bullets in `POST /documents` (where the same gates run).
  - **Placeholders**, filled in when the copy is made: `{{datum}}`/`{{date}}` → today in the app's language (`lib/format.ts`), `{{titel}}`/`{{title}}` → the title of the note the copy goes into; case and spaces inside the braces do not matter. Code blocks and drawings keep them as written; `{{secret:…}}` is no placeholder.
  - **MCP:** `create_note` takes `template` (id or exact title of one of the caller's templates; an exact title first, then ignoring case, an ambiguous title is refused) and builds the same copy on the server (`TemplateBlocksFor` in templates.go: levels from the shallowest bullet, to-dos open and unlinked, conflict copies left out, placeholders filled in with the person's short date, `CreateDocument` runs the media and secret gates); `content` follows below the template's bullets. Reading the template needs `notes:read` besides `notes:create`. `list_notes` shows `isTemplate` and lists only templates with `templates: true`.
- **Link preview:** If a bullet point consists solely of a single `https` URL (or was inserted into an empty bullet via `/link`), MindSift displays an interactive preview card above it (`LinkPreviewCard`, fetched server-side via `/link-preview`). ✕ dismisses the card and synchronously converts the URL to `[Title](url)`.
- **Extract branch (`/extract`):** Converts the current bullet and all its children into an independent note in the same folder. The server creates the note and returns the link; the editor locally replaces the branch via the sync engine as a separate operation (Ctrl+Z reverts the extraction and moves the newly created note to the trash via `POST /documents/{id}/extract/undo`).
- **Inline note:** If a bullet contains only a link to a note (such as after `/extract`), its toolbar displays "Inline note". `POST /documents/{id}/inline` fetches the items of the linked note and moves it to the trash; the editor restores the title (including any hashtags from the link) as text and inserts the items as children, preceding any already existing items. Ctrl+Z or "Undo" restores the link and recovers the note from trash. Only works with own notes, and only as long as no other notes still link to it.
- **Merge notes:** Via drag & drop of one note onto another in the sidebar or via the three-dots menu in the note header ("Merge with another note…"). The source note owned by the user is appended as an `h2` section and moved to the trash; a toast offers full undo (`POST /documents/{id}/merge/undo`).
- **Backlinks:** Under each note, "Linked to this note (n)" lists all notes linking to it (by the note's id, older links without id by title, case-insensitive) along with match locations; clicking jumps directly to the bullet. Without backlinks, the section remains hidden; when collapsed, its state is remembered in the browser ([BacklinksSection.tsx](../../frontend/src/features/workspace/BacklinksSection.tsx), `GET /documents/{id}/backlinks`).
- **Hidden values (`/hidden`, alias `/secret`):** Meant to keep values like passwords off the screen and out of shared or public notes; not a password manager. The API paths, JSON fields, the table `note_secrets` and the reference `{{secret:<id>}}` keep the old name "secret" for compatibility. The sheet sends the value once to `POST /documents/{id}/secrets`; the server stores it encrypted (`note_secrets`, key `SECRETS_KEY`) and the bullet only gets the reference `{{secret:<id>}}`. So API keys, MCP, search, sync, the Markdown export (`••••`) and copying bullets never see the value. A selection of several bullets goes to the clipboard as Markdown with `••••` for other apps and, next to it, in the app's own format `application/x-mindsift-outline` with the references ([outlineMarkdown.ts](../../frontend/src/lib/outlineMarkdown.ts)); pasted into a note, the references go to the server like any other paste. Clipboards that keep only the plain text (headless Firefox, the clipboard API fallback) fall back to the tab's last copy. The bullet shows a lock with dots ([SecretChip.tsx](../../frontend/src/features/workspace/SecretChip.tsx)); a click reveals it through a login-only endpoint for 20 s, with copy and (for editors) change buttons. The value is drawn via CSS `attr()`, so it is not part of the bullet's text. Who can see the note can reveal it, who may edit it can change it. A value belongs to one note: a bullet copied or moved into another note (pasted, moved or merged on the server, extracted, imported) gets a copy of the value there if its writer may read the original note, otherwise the placeholder "(versteckter Wert nicht übernommen)"; from then on the two values are independent ([sharing-and-permissions.md](../sharing-and-permissions.md#hidden-values-in-shared-notes)). Values no live bullet of their note references any more are kept 30 days (undo, trash), then deleted; purging the note deletes its values at once.
- **Links:** Links to notes carry the note's id, so renaming a note or two notes with the same title do not break them: `[[Title#doc_id]]` shows the note's current title, `[[Title#doc_id|Text]]` its own text, `[[Title#doc_id^blk_id]]` links one bullet ("current title › start of the bullet"). The title in the link is only the fallback (no access, deleted note, export). Older links (`[[Title]]`, `[[Title#^blk_id|…]]`) still work by title or bullet id; an update (migration 28) gave existing ones the id where the title was unique. `LinkModal` (Ctrl+L, `/link`) inserts links with id; text marked before Ctrl+L becomes the link text. The display resolves links from the loaded notes ([lib/wikiLinkResolver.ts](../../frontend/src/lib/wikiLinkResolver.ts)); the format is in [lib/wikiLink.ts](../../frontend/src/lib/wikiLink.ts) and [internal/storage/wikilinks.go](../../internal/storage/wikilinks.go). Outside the app links have no ids: AI agents (MCP), the Markdown export (`[[file name]]`, Obsidian's form) and public links see `[[current title]]`; `[[Title]]` written by agents or imported gets the id when the title is unique. Markdown links `[Title](url)` and plain URLs are rendered as tokens.
- **Pasting:** Multiline text is split into blocks based on Markdown prefixes and indentation; headings group subsequent text and code underneath ([pasteOutline.ts](../../frontend/src/lib/pasteOutline.ts)). A Markdown fence (```` ```lang ```` or `~~~`) becomes a code block with that language: known names and short names map to the editor's ids, any other name of 1–40 letters, digits or `+ - _ . #` is kept as written, longer or other names give plain code ([codeLanguage.ts](../../frontend/src/lib/codeLanguage.ts)). A fence can also be a list item's content (```` - ```bash ````): the code block takes that item's level, its code is the lines indented at least as far as the item's text (that indentation taken off), and it ends at the closing fence (at any indentation) or, if that is missing, before the first non-blank line indented less, so the bullets after it stay bullets. The server's Markdown import (MCP `create_note`/`add_note_bullet`, Obsidian and archive import; `itemFence` in [internal/importer](../../internal/importer/), [import_apply.go](../../internal/storage/import_apply.go)) reads it the same way. Pasted HTML with `<pre>` blocks (answers copied from ChatGPT, Claude, documentation pages) is read from its HTML instead of the plain text, which has the code without a fence ([pasteHtml.ts](../../frontend/src/lib/pasteHtml.ts)): each `<pre>` becomes a code block with the language of its `language-…`/`lang-…` class or `data-language`, paragraphs, headings, lists and tables become bullets as their Markdown would; buttons and the language label above the code are left out. Tables, code blocks and drawings never take the text around the cursor: it stays in a bullet before or after them.
- **Pasting images:** An image pasted into a text bullet (Ctrl+V, Cmd+V, paste from the phone's context menu) becomes an image bullet ([pasteImages.ts](../../frontend/src/lib/pasteImages.ts)). It goes the way of the `/image` picker: `prepareImage` shrinks and re-encodes it, `POST /documents/{id}/media` stores it after the server's checks (type, `MEDIA_MAX_IMAGE_MB`). Image files on the clipboard (screenshots, "Copy image") win over the HTML `<img>` and the address browsers add. Files next to real text are dropped when the HTML has no `<img>` (office apps put a picture of the copied cells or text there), otherwise the text is pasted as before and the images follow its last line (their place within the text is not on the clipboard). HTML with only images and no file: https images are copied by the server (`POST /documents/{id}/media/fetch`, same guard as the `/image` link, not in the demo), `data:` images are uploaded. A web page selection with text and images stays a text paste. At most 10 images per paste. While they upload, the bullet shows a placeholder; then an empty text-like bullet becomes the first image and the others (or all, below a bullet with text) follow on its level, in one change (one step for Ctrl+Z). Failures (too big, wrong type, offline: images need a connection) are reported with the error notice. Code blocks, table cells, read-only notes and bullets copied within MindSift (their own clipboard format already holds the image references) are left alone.
- **Dragging images in:** Image files dragged onto a note on a computer (from the desktop or a file manager, or an image dragged out of a browser tab) become image bullets the same way, through the same upload and `handlePasteImages` (`OutlinerTree.tsx`; `draggedFiles`/`droppedImages`/`insertImages` in [pasteImages.ts](../../frontend/src/lib/pasteImages.ts)). Target: the row under the pointer (its text field or the row), between two rows the upper one, below the last bullet, beside the bullets or on the title (`fileDragAtEnd`, wired in `DocumentEditor.tsx`) the last bullet of the note. While files are dragged the target row gets an accent outline (`data-file-drop`, set on the element so the bullets do not re-render), the end of the note the accent line of the area below it. Only drags whose `types` include `Files` count while dragging, so moving a bullet by its handle and dragging text within a field stay as they were; an image out of a browser tab without a file is only known on the drop (its HTML `<img>`, or an image address in `text/uri-list`). A drop's image files always win over the paths and `file://` addresses file managers add; files without an image give the hint "Nur Bilder lassen sich hineinziehen" and are not uploaded. At most 10 images per drop. The placeholder shows below the target bullet. Read-only notes, locked bullets and the public view take no drop; phones have no file drag and drop.
- **Saving:** Every note in the browser runs a `DocSyncEngine` ([lib/docSync/](../../frontend/src/lib/docSync/)). The editor reports any change to the block list; the engine converts them into operations, writes them first to IndexedDB, and sends them batched (300 ms) to `POST /docs/{id}/sync`. When opened, it immediately displays the stored state, even offline.
- **Synchronization for shared or multi-tab notes**, by availability:
  1. **Push** via WebSocket or SSE: The server broadcasts `DOC_SEQ`, the engine syncs immediately (0.2–0.3 s in tests).
  2. **Long-polling** (`/docs/{id}/changes`), when a proxy blocks WebSocket and SSE or buffers SSE: equally fast.
  3. **Polling every 3 s**, if long-polling fails three times in a row (on `online`, long-polling is re-attempted).

  As long as 1 or 2 is running, the engine additionally syncs every 3 s while someone else holds a lease (it can run out without a notice when their browser closes), every 7 s when holding leases itself (renewal), otherwise every 30 s as a safeguard. Focusing a bullet acquires a lease immediately. The editor indicates the connection mode ("Live", "Live (Long-Polling)", "Syncing every 3 s").
- **Cursor stays put:** when changes of others arrive (not own edits), the bullet with the cursor keeps its place on screen: `DocumentEditor` notes its position before applying them (`useDocumentSync`) and scrolls by the difference afterwards (`useEditorLayout`) (also in the journal); for a second after that a `ResizeObserver` on the bullet list evens out later height changes too (new text of a bullet above reaches its field one render later and only then wraps), before they are painted. Without a cursor in the note nothing is adjusted.
- **Private notes** opened in only one tab sync every 30 s, plus immediately upon returning online or switching back to the tab. When leaving, the engine sends pending changes using `keepalive` and releases its leases.
- **Text conflicts:** Each text edit carries the version the user saw while typing. If someone else modified or locked the bullet in the meantime, the server creates a conflict copy; changes are never silently overwritten.
- **Locks (Leases):** The bullet with the cursor, recently left bullets for 7 s (coming back at once, e.g. after a tap on the phone bar, keeps the lock), and newly created bullets are held with a lease; a left bullet is given up with a sync right when its 7 s are over. Bullets held by someone else show a lock with their name, floating in the bullet's top right corner (over text or drawing, so nothing changes width while they type), and are read-only; pressing Enter inside creates a new bullet below. Deleting, merging, indenting/outdenting, and dragging are blocked on locked bullets (notice displayed at the bottom of the editor).
- **Presence:** The note header shows who else currently has the note open.
- **Conflict copies** are highlighted in color ("Conflict – version by …") with "Keep" (text replaces the original bullet or title, and the copy is removed) and "Discard".
- **Undo:** `Ctrl+Z`/`Cmd+Z` reverts the user's last change, `Ctrl+Shift+Z` or `Ctrl+Y` redoes it (also in the title and via context menu/mobile keyboards). Typing in the same bullet up to a 1 s pause counts as one step; up to 200 steps per note. The history of a note survives switching to another note or view and back while the app is open (kept in memory for the last 20 notes, together with what undoing extract/move/inline needs; [lib/docSync/undoHistory.ts](../../frontend/src/lib/docSync/undoHistory.ts)); a reload or logging out clears it. If someone else modified or locked the bullet in the meantime, the step is skipped with a notice.
- `PUT /documents/{id}` only changes icon, pin status, template mark, and folder (title is synced via the log); content changes exclusively run through the engine. The to-do rollup checks off items via a single operation through the same sync endpoint.
- **Note icon (Emoji picker):** Comprehensive emoji catalog with category tabs, search, recently used icons history (`localStorage`), and theme colors. On desktop, compact like a context menu in its own popover without a title bar; on mobile (< 640 px) as a bottom sheet with touch-friendly targets (≥ 44 px) and a `text-base` search input (preventing iOS auto-zoom). The same picker is used when creating notes, task lists, and lists (`EmojiIconButton`). "Remove" clears the icon entirely; without an icon, only the title is shown. New notes start with 🗒️.
- **Multi-bullet selection** ([OutlinerTree.tsx](../../frontend/src/features/workspace/OutlinerTree.tsx)): Dragging with the mouse across bullets selects text across bullet boundaries (CSS Highlight API, falling back to colored lines). Del/Backspace deletes just like a text editor (the remainder of the first and last bullets merge into one, bullets in between including sub-items are removed, sub-items of the last move under the first) in a single step (`onReplaceRange`, a single `Ctrl+Z` recovers everything); typing a character replaces the selection, `Ctrl+C`/`Ctrl+X` copy or cut.

## Explorer, Tags, To-Dos

- Folder tree with favorites (`doc_pins`) and the person's templates marked (`doc_templates`), moving via drag & drop (`/documents/{id}/move`, `/folders/move`). Folders indicate their state via open or closed folder icons (no arrow).
- **Multiple notes** (desktop): Ctrl/Cmd+click selects individual items, Shift+click selects a range in display order (a pinned note appears twice in the tree; the range begins at the clicked location); a normal click, Escape, or clicking into empty space clears the selection. Dragging a selected note moves all selected notes together into a folder or onto the trash (merging is not available in multi-select).
- **Dragging to trash** (including single notes, on mobile via long press like moving into folders) moves items to the trash; a toast offers "Undo".
- **Tags:** All `#hashtags` are aggregated (`/workspace/tags`). A tag page contains its own freeform note (`tag_pages`) and displays below it each note containing matches as a fixed heading, followed by the actual outliner of bullets containing the hashtag along with their children (`DocumentEditor` with `variant="tag"`, separate sync connection per note, loaded only when scrolled into view). Edits apply directly inside the note; a bullet without a hashtag (removed or newly created via Enter) remains visible as long as the cursor is inside it, and disappears once the cursor leaves. Note order is preserved while the page remains open.
- **To-Do Rollup:** The "To-Dos" view aggregates all `todo` blocks across all notes, filterable by folder. Checking off items in the rollup updates the block in the note.
- **Enhanced Tasks:** A `todo` block can be tracked as a linked task (`/documents/{id}/blocks/{blockId}/enhanced-task`); completion status stays synchronized between note and task view.

## Trash

- Deleting (individually or with a folder) moves user-owned notes to the trash (`is_archived = 1`). Deleting a shared note not owned by the user merely removes their share.
- Notes in the trash are excluded from the tree, search, export, and stats, and are invisible to all recipients (`DocRole` = no role). Owners and deleting users see them read-only with an info banner and "Restore"; rename, move, and share actions are rejected.
- A "Trash" entry with a counter sits at the bottom of the folder sidebar and in the mobile menu. The list displays folder and deletion timestamp; "Delete permanently" and "Empty trash" require a second confirmation tap.
- Restoring recreates a previously deleted folder; if a shared folder no longer exists, the note is placed at the root level. Shares remain intact. After the owner's retention period expires (Account Settings → Data Retention, default 30 days after deletion), the server permanently deletes the note ([retention.go](../../internal/storage/retention.go)).

## Sharing

- Individual notes and entire **shared folders** can be shared with users or groups – with either the **Editor** (`write`) or **Viewer** (`read`) role ([sharing-and-permissions.md](../sharing-and-permissions.md)). Editors modify content and structure via the sync engine; viewers see changes live.
- Recipients organize shared notes and folders within their own folder tree (`doc_user_folders`, `workspace_folder_mounts`) without affecting the owner's hierarchy.
- Changes reach open windows via the `DOC_SEQ` wake-up call followed by sync; note lists update via `DOC_UPDATED` (the note as the list has it, without bullets), `DOC_COUNTS` (open to-dos and hashtags of a note whose bullets someone changed, at most every 3 s per note and only when they changed) and `WORKSPACE_FOLDERS_UPDATED`, whose `type` decides whether the list is fetched again ([websocket.md](../api/websocket.md)).
- The app's note list holds bullets only for notes open in an editor (their counts follow typing); when the editor closes, the list drops them and keeps their counts in the list's fields, which the server's events then keep current.

## Limitations

- No concurrent editing within the same individual bullet (per-bullet leases and conflict copies instead of character-by-character merging), no remote cursor display, no version history.
- No virtualization for long documents; very large notes may become sluggish on mobile devices *(unmeasured)*.
- ~~Search (`/search`) only covers titles and contents of personal notes~~: With global FTS5 search (`Cmd+K` / `Ctrl+K` / `/`), both titles and block contents of all accessible notes (personal and shared) are searchable.

## Export as Markdown Archive

Account Settings → Export & Import → "Download Markdown archive" (`GET /export/markdown`, code: [export_markdown.go](../../internal/storage/export_markdown.go)).

- Folders and notes reflect the user's view (own folders, mounted shared folders, notes shared with them); empty folders are preserved, also folders that came into being through a note (made in a new folder path or moved there).
- Each note: YAML frontmatter (`title`, `icon`, `tags`, `created_at`, `updated_at`) and Markdown formatted for immediate rendering in Obsidian: top-level headings, dividers, callout boxes (`> [!note]`), and code blocks as top-level blocks with their children shifted forward one level; everything else as a list indented with one tab per level, to-dos formatted as `- [ ]`.
- Filenames are sanitized across operating systems (no `/ \ : * ? " < > |`, never `.`/`..`); duplicate titles receive " (2)".
- The ZIP is streamed directly to the response while reading data, without temporary files.

## Import

Account Settings → Export & Import → "Import Data", with **two separate paths** (code: [internal/importer](../../internal/importer/), [import_apply.go](../../internal/storage/import_apply.go), [ImportCard.tsx](../../frontend/src/features/settings/ImportCard.tsx)):

| Method | Endpoint | Files | Result |
|---|---|---|---|
| MindSift Data | `POST /import/mindsift` | Backup ZIP or JSON (`/export`) or Markdown archive (`/export/markdown`), format is auto-detected | Notes placed in their folders, task lists with subtasks, due dates, priorities, and notes, lists with quantities, categories, and completion status, plus Triage thoughts for JSON backups. Third-party content merely shared with the exporter in JSON is skipped. |
| Obsidian Vault | `POST /import/obsidian` | ZIP of a vault | Everything imported into a new folder named after the vault, preserving subfolders. Checkboxes remain checkboxes, frontmatter tags become `#hashtags`, callouts become callout boxes, wikilinks remain `[[…]]`. Hidden folders (`.obsidian`, `.trash`) are ignored, attachments skipped. |

- **Preview:** The UI first uploads the file with `?preview=1`. The server reads and validates everything, reporting what would be created (including skipped files with reasons), but writes nothing. Only clicking "Import now" creates the data.
- **Append or Restore** (MindSift data only): "Append" only adds new items; existing items remain unchanged. "Restore" (`?mode=restore`, in the UI only after confirming a warning dialog) wipes all existing personal notes, folders, tasks, thoughts, and lists beforehand – only after the file has been fully read and validated, so a corrupted file will not erase anything. Third-party content shared with the user is retained. Obsidian import always appends.
- **Markdown → Note:** Lists preserve their nesting (tabs or spaces), content under a heading is indented beneath it (counterpart to export), paragraphs become bullets, code blocks become code blocks.
- **Limits:** Upload max 100 MB, single note max 10 MB, uncompressed total max 500 MB, at most 20,000 files. Paths containing `..` or absolute paths are sanitized and contained within the target folder.
- If an import aborts due to an error, items created up to that point are retained; the error message identifies the element that failed.
