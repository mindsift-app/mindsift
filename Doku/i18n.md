# Languages

MindSift speaks German, English, Spanish, French and Italian. German is the source language: texts are written in German first, every other language translates them. How it works: [architecture.md](architecture.md#languages).

## Where the texts live

| What | Where |
|---|---|
| Interface | `frontend/src/locales/<code>/<area>.json` (i18next, `{{placeholder}}`, plurals as `_one`/`_other`) |
| In-app help | `frontend/src/features/help/content/<code>.tsx` |
| Server texts (errors, mails, push, summary, columns, journal) | `internal/i18n/messages_<code>.go`, keyed by the German text, `{placeholder}` |
| Dates and times in server texts | `internal/i18n/format.go` |
| App description and shortcuts (`manifest.json`, `index.html`) | `staticTexts` in `internal/api/server.go`, translated through the server catalog |
| Sample data and help notes of new accounts | `internal/storage/seed.go` (German), `seed_en.go` (English, for every other language) |

## Adding a language

1. **Interface:** copy `frontend/src/locales/en/` to the new code and translate the values (keep the keys and `{{placeholders}}`). Add the code to `LANGUAGES` and `loaders` in `frontend/src/i18n/index.ts`.
2. **Help:** copy `features/help/content/en.tsx` and add its loader to `loaders` in `content/index.ts` (tsc fails without it). Each language's help is a chunk of its own, loaded the first time the help opens in that language; if it cannot be loaded, the German help shows.
3. **Server:** copy `internal/i18n/messages_en.go` to `messages_<code>.go`, translate the values (keep the German keys and `{placeholders}`), register it in `catalogs` (`messages.go`), add a date format to `format.go` and the code to `Supported` (`i18n.go`).
4. **Check:** `npx vitest run src/i18n` (every language has the German keys and placeholders) and `go test ./internal/i18n/` (every German server text has a translation, every supported language a catalog and date format).

A server text a catalog lacks shows in English; an interface text a language lacks shows in German.

An API answer is in the language of `Accept-Language` when MindSift speaks it (the app always sends its own), else in the server's default language, else in English: a script without the header gets English errors, not the German keys' language. The sign-in screen and new accounts still fall back to German while no default language is set.

## Why error texts are German sentences

Go's convention is error texts in lower case, in English and without a full stop, because they end up inside other messages (`open config: file does not exist`). MindSift keeps to it for errors that stay inside the server (`fmt.Errorf("reorder: %w", err)`): they are logged, and the client only reads "Internal error – the details are in the server log".

An error a person gets to read is different. It is the sentence shown in the app, and its German original is the key the catalogs translate: `errors.New("E-Mail-Adresse existiert bereits")` leaves the server as "This email address already exists" for an English browser. Such errors are therefore whole German sentences with a capital letter, and a test fails when a catalog lacks one of them. For the same reason `staticcheck.conf` switches off the check ST1005, which would flag every one of these texts.

## Rules for new code

- Interface: no fixed text in JSX, attributes (`title`, `aria-label`, `placeholder`) or messages; use `t('…')` or `i18n.t('area:…')` and add the key to every language.
- Server: write the German text through `writeError`, `tr`, `i18n.T(lang, …)` or `i18n.NewError` and add it to every catalog; the catalog test lists what is missing. Messages to a person use `userLanguage` (API) or `MessageLanguage` (store), MCP and OAuth use English.
